# AI-Enhanced Infrastructure Deployment PoC

> ⚠️ **This is a demo application, not a production reference.** The Terraform code generated by this system is **intentionally not security-hardened**. The purpose of this demo is to produce GitHub pull requests containing infrastructure code that [AWS Security Agent](https://docs.aws.amazon.com/securityagent/latest/userguide/) can review and flag for security issues. **Do not deploy the generated code in production environments.**

## Overview
This PoC demonstrates an AI-Enhanced AWS Infrastructure Deployment and Management System. It uses Amazon Bedrock to generate Terraform code from natural language requests with intelligent context awareness and targeted updates. The generated pull requests are then reviewed by AWS Security Agent to showcase its code review capabilities — identifying security misconfigurations, missing encryption, overly permissive policies, and other vulnerabilities in AI-generated infrastructure code.

## Architecture

```
┌─────────────┐    ┌──────────────┐    ┌─────────────────┐
│   Client    │────│ API Gateway  │────│   Lambda        │
│  Request    │    │   (REST)     │    │   Function      │
└─────────────┘    └──────────────┘    └─────────────────┘
                                               │
                                               ▼
                   ┌─────────────┐    ┌─────────────────┐
                   │   Bedrock   │◄───│  Context        │
                   │  (Claude)   │    │  Processing     │
                   └─────────────┘    └─────────────────┘
                                               │
                                               ▼
┌─────────────┐    ┌──────────────┐    ┌─────────────────┐
│   GitHub    │◄───│      S3      │◄───│  File Analysis  │
│    Repo     │    │   Context    │    │  & Selection    │
└─────────────┘    └──────────────┘    └─────────────────┘
       │
       ▼
┌─────────────┐
│ Pull Request│
│  Created    │
└─────────────┘
```

### Components
- **Lambda Function**: Intelligent Terraform code processor with context awareness
- **Amazon Bedrock**: AI model for code generation and updates (defaults to Claude Sonnet 4, configurable via `BEDROCK_MODEL_ID`)
- **S3**: Stores organizational context, tags, and summaries
- **API Gateway**: REST API endpoint for infrastructure requests
- **GitHub API**: Automated PR creation and file management
- **Context Engine**: Smart file selection and code summarization

## Deployment

### Prerequisites
- AWS CLI configured
- Terraform installed
- GitHub repository with secrets configured

### Steps
1. Clone repository
2. Upload `it-operations-tags.json` to S3 bucket
3. create lambda_function.zip in the terraform folder
4. Deploy using manual Terraform

### Manual Deployment
```bash
cd terraform
terraform init
terraform plan
terraform apply
```

## Lambda Function Flow

### 1. Request Processing
```
Incoming Request → Operation Detection → Resource Identification
```
- **Operation Detection**: Distinguishes between CREATE and UPDATE operations
- **Resource Identification**: Maps request keywords to AWS resource types
- **File Path Extraction**: Determines target file location

### 2. Context Intelligence

#### For CREATE Operations:
```
Resource Types → File Selection → Summarization → Context Building
```
- Fetches only relevant Terraform files based on resource types
- Generates concise summaries (resource count + key attributes)
- Limits context to prevent token overflow

#### For UPDATE Operations:
```
Target File → Block Extraction → Relevant Sections → Targeted Context
```
- Extracts specific resource blocks from target file
- Focuses on mentioned resources (VPC, EC2, etc.)
- Provides surgical precision for updates

### 3. AI Code Generation
```
Context + Request → Bedrock (Claude) → Generated Code → Validation
```
- **CREATE**: Generates new Terraform code with infrastructure awareness
- **UPDATE**: Modifies only specified parts while preserving existing code
- Includes organizational tags and AWS best practices

### 4. GitHub Integration
```
Generated Code → Branch Creation → File Commit → PR Creation
```
- Creates unique timestamp-based branches
- Handles file creation and updates with proper SHA management
- Generates descriptive pull requests with context

### 5. Scalability Features
- **Smart File Selection**: Only processes relevant files (not all 100+ files)
- **Block-Level Updates**: Extracts specific sections for large file updates
- **Token Management**: Keeps API calls under limits regardless of codebase size
- **Context Summarization**: 10MB files → ~500 byte summaries

## Usage

```json
{
  "request": "Create a VPC with public and private subnets in new file vpc/main.tf"

```

### Update Existing Infrastructure
```json
{
  "request": "In generated/main.tf update the EC2 instance type to t3.medium"
}
```

### Response Format
```json
{
  "terraform_code": "resource \"aws_vpc\" \"main\" {...}",
```

## Configuration

### Environment Variables
```bash
CONTEXT_BUCKET=your-s3-bucket
GITHUB_TOKEN=your-github-token
GITHUB_OWNER=your-github-username
GITHUB_REPO=your-repo-name
```

### Files
- **`variables.tf`**: Terraform configuration settings
- **`it-operations-tags.json`**: Organizational tags and metadata
- **GitHub Secrets**: AWS credentials for deployment

### Supported Operations
- **CREATE**: `create`, `add`, `new`, `generate`, `build`
- **UPDATE**: `update`, `modify`, `fix`, `change`, `correct`, `adjust`

### Supported Resources
- **EC2**: instance, server, vm, compute
- **VPC**: network, subnet, vpc
- **RDS**: database, db, mysql, postgres
- **S3**: bucket, storage
- **ELB**: load balancer, alb, nlb
- **EBS**: volume, disk
- **IAM**: role, policy, user, permission
- **Security**: security group, firewall
